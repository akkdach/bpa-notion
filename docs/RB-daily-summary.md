## ตั้งค่าครั้งแรก (ต่อเครื่อง)

### 1. ติดตั้ง GitHub CLI

```powershell
winget install --id GitHub.cli
```

**ปิด terminal แล้วเปิดใหม่** หลังติดตั้ง ไม่งั้นยังหาคำสั่ง `gh` ไม่เจอ

### 2. ล็อกอิน GitHub

```powershell
gh auth login
```

ตอบตามลำดับ: **GitHub.com** → **HTTPS** → **Login with a web browser** →
คัดลอกรหัส 8 หลัก → Enter → เบราว์เซอร์เปิด → วางรหัส → Authorize

ตรวจ: `gh auth status` ต้องขึ้น `Logged in to github.com as <ชื่อ>`

> ⚠️ ขั้นนี้ **AI ทำแทนไม่ได้** — ต้องยืนยันตัวตนผ่านเบราว์เซอร์ด้วยตัวเอง

### 3. ติดตั้งตัวคำสั่ง — เลือกทางใดทางหนึ่ง

| ทาง | ทำยังไง | ใช้ได้เมื่อไหร่ |
| --- | --- | --- |
| **project scope** (ไม่ต้องทำอะไร) | clone repo นี้ก็ได้ไปเลย | เฉพาะตอนเปิด Claude Code ในโฟลเดอร์ repo นี้ |
| **user scope** | copy `.claude/commands/summary.md` ไปที่ `%USERPROFILE%\.claude\commands\` | ทุกโฟลเดอร์บนเครื่องนั้น |

```powershell
# ทาง user scope
New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\commands" | Out-Null
Copy-Item .claude\commands\summary.md "$env:USERPROFILE\.claude\commands\"
```

⚠️ ทาง user scope เป็น **สำเนา** — แก้ไฟล์ในโปรเจกต์แล้วต้อง copy ทับใหม่

### 4. ปิด Claude Code แล้วเปิดใหม่

  แยกหัวข้อรายคนพร้อมเวลา → บั๊กสำคัญติด 🔴 พร้อมอาการและสาเหตุ → รายการค้าง

## ใครเห็นอะไรได้บ้าง (สำคัญสำหรับคนที่ไม่ใช่เจ้าของ repo)

คำสั่งดึงข้อมูลด้วย **บัญชี GitHub ของคนที่รัน** — เห็นได้เท่าที่บัญชีนั้นมีสิทธิ์เห็น

| สถานะของคนรัน                              | เห็นอะไร                                     |
| ------------------------------------------ | -------------------------------------------- |
| เจ้าของบัญชี `akkdach`                     | ทุก repo ทุก commit                          |
| **collaborator** ของ repo นั้น             | commit ของ **ทุกคน** ใน repo นั้น รวมของคนอื่น |
| ไม่ได้ถูกเชิญเข้า repo (และ repo เป็น private) | **ไม่เห็นเลย** — repo นั้นจะไม่โผล่ในสรุป      |

**ข้อสำคัญ:** เป็น collaborator แล้วเห็น commit ของ **ทุกคน** ไม่ใช่แค่ของตัวเอง —
GitHub ไม่ได้กรองรายบุคคล กรองที่ระดับ repo เท่านั้น

> ⚠️ **กับดักที่แก้ไปแล้ว** — `gh repo list akkdach` เมื่อรันจากบัญชี *คนอื่น*
> จะคืนเฉพาะ repo **public** เท่านั้น (GitHub API `/users/{name}/repos` เป็นแบบนั้น)
> private repo ที่เราถูกเชิญเข้าไปจะไม่โผล่ ทำให้สรุปว่างเปล่าทั้งที่มีสิทธิ์อยู่ ·
> คำสั่งจึงรวมผลจาก `user/repos?affiliation=collaborator` เข้ามาด้วยแล้ว dedupe

ถ้าคนในทีมรันแล้วได้ **"ไม่พบ repo ที่เข้าถึงได้"** = ยังไม่ถูกเชิญเข้า repo —
ให้เจ้าของบัญชี `akkdach` เชิญเป็น collaborator ก่อน (Settings → Collaborators)

### 🔴 ผลข้างเคียง: คนละคนรันได้ผลไม่เท่ากัน

คนที่เข้าถึง 3 repo จะได้สรุปแค่ 3 repo · คนที่เข้าถึงครบจะได้ครบ —
**หน้าสรุปรายวันจึงถูกเขียนทับด้วยฉบับที่ไม่ครบได้** ถ้าคนสิทธิ์น้อยรันทีหลัง

คำสั่งมีด่านกันไว้แล้ว: ก่อนเขียนทับจะอ่านของเดิมมาเทียบ ถ้าของเดิมมี repo หรือชื่อคน
ที่บัญชีปัจจุบันมองไม่เห็น **จะไม่ทับ** แต่จะเติมเฉพาะรายการใหม่แล้วแจ้งผู้ใช้

**ทางแก้ที่ต้นเหตุ — เลือกอย่างใดอย่างหนึ่ง:**

| ทาง | ทำยังไง | เหมาะเมื่อ |
| --- | --- | --- |
| **กำหนดคนรัน** | ให้คนที่เข้าถึงครบทุก repo เป็นคนรัน `/summary` คนเดียว | ทีมเล็ก จัดการง่ายสุด |
| **เชิญทุกคนเข้าทุก repo** | GitHub → แต่ละ repo → Settings → Collaborators | ทุกคนควรเห็นงานกันอยู่แล้ว |
| **ย้ายไป Organization** | สร้าง GitHub Organization แล้วโอน repo เข้า จัดสิทธิ์เป็น team | ระยะยาว ทีมโตขึ้น — จัดสิทธิ์ทีเดียวได้ทุก repo |

## ข้อจำกัด

| ไม่เห็นอะไร                                 | ทำไง                                    |
| ------------------------------------------- | --------------------------------------- |
| งานที่ commit แล้วแต่ **ยังไม่ push**       | push ก่อนรันคำสั่ง                      |
| repo private ที่ **ยังไม่ถูกเชิญเข้า**      | ขอสิทธิ์ collaborator จากเจ้าของ repo   |
| งานที่ **ไม่ใช่โค้ด** (ประชุม ตรวจระบบ)     | เขียนเพิ่มเอง หรือบอก AI ให้เติม        |
| repo ที่ **ไม่ได้อยู่ใต้บัญชี `akkdach`**   | ยังไม่รองรับ — ต้องแก้ `$owner` ในคำสั่ง |
